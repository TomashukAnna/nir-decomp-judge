# Кандидаты для расширения банка требований

Это рабочая группировка для просмотра, а не готовый банк и не кластеризация эмбеддингов.
Группы заданы вручную; поисковые выражения только отбирают возможные примеры.
Отдельные совпадения ещё не проверены по смыслу.
Один пункт может попасть в несколько групп.
Исходные требования, их типы code/llm и старый банк не изменены.

## Файлы

- [catalog.json](catalog.json): все исходные требования с уникальными ссылками.
- [candidates.json](candidates.json): группы, их параметры и полные списки исходных ID.
- [review.md](review.md): формулировки внутри каждой группы и пункты без группы.
- [neighbors.csv](neighbors.csv): до пяти ближайших требований из других ТЗ по TF-IDF.
- [map.html](map.html): карта TF-IDF + TruncatedSVD, открывается без интернета.
- [manifest.json](manifest.json): контрольные суммы и инвентаризация, не метрики судьи.

## Группы

| Группа | Что обобщаем | Что требуется уточнить |
|---|---|---|
| Вход в систему (`auth.login`) | Пользователь указанной роли может войти в систему. | Разделить наличие формы и успешный вход; не придумывать учётные данные и способ авторизации. |
| Регистрация (`auth.registration`) | Пользователь может зарегистрировать учётную запись. | Исключить регистрацию заявок, заказов и событий; сохранять заданные роли. |
| Доступ в личный кабинет (`account.access`) | Пользователь может открыть свой личный кабинет. | Связать с одноимённым шаблоном старого банка; не включать автоматически редактирование профиля. |
| Просмотр своих данных (`account.view_own_information`) | Пользователь может просмотреть данные своего профиля. | Связать со старым банком; просмотр любых пользователей и просмотр собственных данных различаются. |
| Изменение профиля (`account.edit_profile`) | Пользователь может изменять данные своего профиля. | Разделить изменение своего профиля и управление чужими учётными записями; не добавлять поля от себя. |
| Просмотр списков и каталогов (`collection.browse`) | Пользователь может просмотреть коллекцию объектов заданного типа. | Сохранить тип объектов и ограничения видимости; карточка одного объекта — отдельная проверка. |
| Просмотр сведений об объекте (`entity.details`) | Пользователь может просмотреть сведения об объекте. | Составные требования к карточке могут потребовать разделения; обязательные поля берутся только из ТЗ. |
| Поиск (`collection.search`) | Пользователь может находить объекты по запросу. | Наличие поля поиска и корректные результаты различаются; поиск по тексту и по категории не равнозначны. |
| Фильтрация (`collection.filter`) | Пользователь может ограничить набор объектов выбранными условиями. | Не приписывать фильтры, которых нет в ТЗ; не смешивать фильтрацию данных с сетевыми фильтрами. |
| Создание объекта (`entity.create`) | Пользователь может создать объект заданного типа. | Создание сущности, добавление связи и настройка интерфейса могут требовать отдельных шаблонов. |
| Редактирование объекта (`entity.update`) | Пользователь может изменить существующий объект. | Изменение записи, конфигурации и состояния процесса пока не считать одной исполняемой проверкой. |
| Удаление объекта (`entity.delete`) | Пользователь может удалить существующий объект. | Удаление объекта и исключение его из подборки различаются; не придумывать подтверждение удаления. |
| Отправка формы (`form.submit`) | Пользователь может отправить заполненную форму. | Заполнение и отправка — разные действия; форма не доказывает сохранение или доставку данных. |
| Валидация ввода (`form.validation`) | Система проверяет заданные ограничения на ввод. | Проверять только ограничения из ТЗ или явно отмеченные трактовки; не добавлять требования к паролю. |
| Загрузка файлов в приложение (`file.upload`) | Пользователь может передать файл приложению. | Уточнить направление передачи; загрузка картинки браузером не равна пользовательскому upload. |
| Скачивание файлов (`file.download`) | Пользователь может скачать выбранный ресурс. | Проверять получение содержимого, а не одну кнопку; учитывать права доступа, если они заданы. |
| Экспорт (`data.export`) | Пользователь может экспортировать данные. | Экспорт не всегда означает скачивание; не добавлять CSV или PDF, если формат не задан. |
| Сообщения и чат (`communication.messages`) | Пользователи могут обмениваться сообщениями. | Отделить чат между пользователями, системное уведомление, ошибку и ответ бота. |
| Комментарии и обсуждения (`content.comments`) | Пользователь может участвовать в обсуждении объекта. | Разделить просмотр и публикацию; отзыв с оценкой не обязательно является обычным комментарием. |
| Корзина (`commerce.cart`) | Пользователь может выполнить указанную операцию с корзиной. | Разделить добавление, изменение количества и удаление; открытие корзины не подтверждает остальные операции. |
| Оплата (`commerce.payment`) | Пользователь может оплатить выбранную услугу или заказ. | Способы оплаты — параметры; интеграция платёжного провайдера и форма-заглушка различаются. |
| Бронирование (`booking.create`) | Пользователь может забронировать выбранный ресурс. | Разделить создание, просмотр, отмену и управление бронированиями; сохранять временные ограничения. |
| Заказы (`commerce.orders`) | Пользователь может выполнить заданное действие с заказом. | Разделить оформление, просмотр, изменение статуса и отмену; пока это тематическая семья. |
| Права доступа (`access.permissions`) | Операция или раздел доступны только разрешённым ролям. | Отделить управление правами и применение запрета; наличие админ-панели не доказывает защищённость. |
| Администрирование (`admin.management`) | Администратор может управлять заданными объектами. | Тематическая семья: управление пользователями, контентом и настройками требует отдельных шаблонов. |
| Отчёты и аналитика (`analytics.reports`) | Пользователь может получить заданное представление данных. | Картинка, вычисление показателя и отчёт не равнозначны; график работы исключить из аналитики. |
| Расписание и календарь (`schedule.calendar`) | Пользователь может просмотреть или изменить расписание. | Разделить отображение календаря, создание события и выбор времени; не придумывать предотвращение конфликтов. |
| Цвет фона (`ui.background_color`) | Заданная область фона имеет указанный в ТЗ цвет. | Основной фон, внешний слой и фон всех страниц различаются по области. Не придумывать HEX для неизвестного названия. |
| Цвет компонентов (`ui.component_color`) | Заданные элементы интерфейса имеют указанный цвет. | Цвет всех компонентов, кнопок и отдельных акцентов — разные области проверки; сохранить формулировку ТЗ. |
| Адаптивность интерфейса (`ui.responsive`) | Интерфейс пригоден для указанных устройств или размеров экрана. | Поддержка мобильного браузера и отдельное мобильное приложение различаются; не придумывать размеры экрана. |

## Как перейти от групп к банку

Просмотреть review.md: исключить ложные совпадения, разделить составные требования,
выделить параметры и сохранить роли, ограничения и зависимости. Сходство действий
не означает одинаковую проверку.
Например, создание записи и добавление товара в корзину различаются.
Пункты без группы не считаются автоматически специфичными.
Часть могла не совпасть по словам.

У подтверждённого шаблона должны быть условия применимости, ссылки на исходники и правило
проверки. Метка code в исходной разметке не означает, что проверяющий код уже написан.
Проверку цвета из первой версии банка можно сохранить.
Новые checker здесь не заявляются.
Неподтверждённые группы в configs/requirement-bank.json не добавляются.

## Повторение

Из корня проекта, в новую папку результатов:

```powershell
uv run python -m decomp_judge.bank_candidates `
  --output results/requirement-bank-expansion-repeat
```

Используются локальные data/requirements/*.json и data/requirements/train/*.json
и соответствующие Markdown. Нужны исходные разборы, а не вложенная рабочая копия Git.
Сеть, модели, эмбеддинги и API не используются.
TF-IDF считается по русским формулировкам требований.
Файлы существующего запуска не перезаписываются. SEED задаёт случайность проекции.
Подбор по TF-IDF основан на символах длиной 3–5 и косинусном сходстве.
Высокая близость не доказывает эквивалентность.
Отрицания, роли и условия могут различаться.
