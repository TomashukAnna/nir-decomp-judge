# Отбор ТЗ для расширения банка

Пробная кластеризация использует только train WebGen-Bench. Test не читается.
Это подготовка кандидатов для ручной разметки, а не оценка качества судей.

## Воспроизведение

Из чистого committed checkout, после `uv sync --locked`:

```powershell
$env:SEED = '42'
uv run python -m decomp_judge.train_sampling --config configs/train-sampling.yaml
```

Путь к train, каталогу уже размеченных ТЗ и выходному каталогу задаётся в YAML.
Относительные пути разрешаются от рабочего каталога. Для повторного запуска
нужно выбрать новый output; существующие результаты не перезаписываются.
MLflow использует переменные окружения и локальное хранилище по умолчанию,
не читая `.env`. Внешние API, модели и сетевые сервисы не используются.

## Метод

Из текста удаляются самостоятельные инструкции о цветах, начинающиеся
с глаголов оформления, и несколько шаблонных вводных фраз. Исходное ТЗ сохраняется.
Эта эвристика не гарантирует удаления всех стилистических инструкций.
Совпавшие очищенные тексты объединяются до построения TF-IDF и SVD.
KMeans сравнивается на сетке из конфига по косинусному silhouette на фиксированной
выборке. Это выбор предварительного разбиения, а не оптимизация покрытия функций.

В каждой группе выбирается доступный пример, ближайший к среднему вектору,
а затем примеры, наиболее удалённые от уже выбранных в этой группе.
Точные совпадения с очищенными текстами размеченного банка исключаются.
Порог косинусной близости к ранее выбранным примерам действует между группами;
порядок групп может влиять на отбор. Маленькие или однообразные группы могут
дать меньше кандидатов. Парафразы уже размеченных ТЗ могут остаться.

## Артефакты

В игнорируемом Git выходном каталоге:

- `run.json`: commit, seed, MLflow run ID, SHA-256 train, сравнение вариантов,
  размеры групп, ключевые слова, исходные application_type и отобранные ID;
- `membership.csv`: кластер каждой исходной записи и ID её канонического текста;
- `candidates.jsonl`: исходные ТЗ с причиной выбора и очищенным текстом;
- `candidates.md`: подборка для чтения и последующей ручной разметки.

В MLflow записываются конфиг, параметры, метрики и сводка без полных ТЗ.
Проверка: `make check`.

## Ручная проверка

Просмотреть центральные и разнообразные примеры каждой группы; проверить, что
различаются функции, а не только предметная область. Отметить дубли и примеры,
не добавляющие требований к банку. Номера кластеров не являются категориями.
После проверки можно менять число групп или сравнить с готовыми BGE-M3-векторами.
Состав итоговой проверочной выборки для судей пока не определяется.

Черновик решения: [ADR-0001](adr/0001-train-cluster-sampling.md).
