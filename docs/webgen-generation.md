# Генерация приложений по 101 ТЗ WebGen-Bench

OpenCode 1.19.4 работает в Linux-контейнере на ноутбуке. Модель
`iairlab/qwen3.8-27b` вызывается по API `https://api.duckduck.cloud/v1`;
веса модели на ноутбук не скачиваются. Одновременно генерируется одно приложение.
Генератор получает только поле `instruction`, без нашей разметки и оценок судей.

## Где будут приложения

По умолчанию — `data/generated-apps/webgen-qwen-001/` в этом проекте:

```text
webgen-qwen-001/
  manifest.json             # версия кода, SHA-256 входа, модель, лимиты, seed
  summary.csv               # состояние каждого из 101 заданий и MLflow run ID
  status.json               # количества по состояниям
  mlflow.db                 # локальные запуски генерации
  mlartifacts/              # артефакты MLflow
  task-000001/
    spec.txt
    app/                    # сгенерированное приложение
    run.json                # статус, версия, время и run ID
    files-sha256.json       # контрольные суммы исходников успешной генерации
    raw-output.jsonl        # локальная трасса OpenCode
  task-000002/
    ...
```

Это папка на диске ноутбука, подключённая к контейнеру. Остановка или удаление
контейнера её не удаляет. Данные и приложения не коммитятся в Git; код генератора,
конфигурация, инструкции и итоговые сводки эксперимента публикуются отдельно.
`node_modules`, `.venv`, служебный `.git` и Python-кэш удаляются из успешно
сгенерированного приложения; исходники и lock-файлы остаются.

## Подготовка

Команды — из корня проекта в PowerShell. Docker Desktop должен быть запущен.
Исходный файл по умолчанию: `../data WebGen-Bench/test.jsonl`.
Другой путь можно передать параметром `-InputPath`.

Ключ используется только из окружения процесса. Если он уже сохранён в Windows:

```powershell
$env:LITELLM_API_KEY = [Environment]::GetEnvironmentVariable('LITELLM_API_KEY', 'User')
```

Не выводите ключ на экран и не вставляйте его в Dockerfile или команды с его значением.

После коммита изменений соберите образ и проверьте вход без модели:

```powershell
.\scripts\webgen.ps1 -Action Build
.\scripts\webgen.ps1 -Action Check
```

Сборка требует чистого checkout и фиксирует его коммит внутри образа. Базовые
образы закреплены digest, версия OpenCode закреплена. Пакеты Debian и зависимости
создаваемого приложения могут обновляться; это не полная побайтовая воспроизводимость.

## Сначала одно приложение

```powershell
.\scripts\webgen.ps1 -Action Pilot
```

Пилот обрабатывает первое ещё не запущенное ТЗ и останавливается. В свежей партии
это индекс 0, WebGen ID 000001. Проверить файлы можно в `task-000001/app/`.
GENERATED означает, что созданы исходники, а не что все требования выполнены.
Пилот остаётся частью общей партии, повторно генерировать его при Start не нужно.

## Ночной запуск и контроль

```powershell
.\scripts\webgen.ps1 -Action Start
.\scripts\webgen.ps1 -Action Status
```

Start продолжает партию в фоне. PowerShell можно закрыть. Ноутбук должен оставаться
включённым, подключённым к питанию и интернету; сон, закрытие крышки с переходом
в сон и остановка Docker приостанавливают или обрывают работу. Контейнер не переносит
вычисления на сервер: удалённо выполняется только вызов LLM.

Сколько ТЗ удастся выполнить за ночь, определяем по пилоту и реальному темпу.
На число шагов агента и полное время генерации приложения ограничений нет
(`max_steps: null`, `timeout_seconds: null`). Локальный плагин
`configs/webgen-no-output-cap.mjs` убирает стандартный лимит OpenCode в 32 000
токенов: поле ограничения длины ответа не отправляется в API. Действуют
ограничения и значения по умолчанию сервера модели; это не бесконечный ответ.
Сетевые тайм-ауты OpenCode и отдельных shell-команд также остаются.
Зависшую или слишком долгую генерацию можно остановить командой Stop.
Плагин подключается только для генератора; режим `--pure` здесь не используется,
поскольку он отключает и этот плагин. Конфигурации проекта, встроенные плагины и
внешние навыки по-прежнему отключены, домашний каталог контейнера изолирован.
После трёх неудач подряд партия останавливается для проверки API и среды.

Остановить и затем продолжить оставшиеся задания:

```powershell
.\scripts\webgen.ps1 -Action Stop
.\scripts\webgen.ps1 -Action Resume
```

Сгенерированные приложения не перезаписываются; контрольные суммы проверяются.
FAILED и INTERRUPTED также сохраняются и не перегенерируются автоматически.
Прерванный процесс с записью RUNNING при Resume помечается INTERRUPTED.
Для неудачных задач сначала разбираем причину и отдельно согласуем повтор —
скрытых повторных попыток и выбора лучшего приложения здесь нет.

Нельзя продолжить ту же партию с другим входным файлом, промптом, коммитом или
настройками. Для другого эксперимента укажите новую `-OutputPath` внутри `data/`.
Одновременный запуск двух процессов на одной партии блокируется файловой блокировкой.

## MLflow и результаты

Каждая попытка имеет отдельный MLflow run: параметры, seed из `SEED` (по умолчанию 42),
статус, время, число исходников и опубликованные OpenCode счётчики токенов.
Seed фиксируется, но не навязывается модели. Токены относятся к событиям
`step_finish` и не гарантируют совпадение с биллингом API.

Для быстрого контроля достаточно `summary.csv`, `status.json` и `task-*/run.json`.
База MLflow относится к этой партии. Её артефакты записаны по контейнерному пути
`/output/mlartifacts`; для открытия MLflow UI нужно подключить тот же каталог
как `/output`, а не считать, что внешние пути автоматически перенесены на Windows.

Существующая конфигурация судьи `opencode.json` не изменяется. Генератор строит
свою конфигурацию из `configs/webgen-generation.yaml` и `configs/webgen-builder.md`.
Ему разрешены создание файлов и shell-команды внутри контейнера. Каталог проекта,
домашняя папка Windows и Docker socket в контейнер не подключаются.

## Проверки без ключа

```powershell
uv run python -m decomp_judge.webgen_generate --input '..\data WebGen-Bench\test.jsonl' --output data/generated-apps/check
make check
```

Без `--execute` ключ не читается, файлы не создаются и запросов к модели нет.
