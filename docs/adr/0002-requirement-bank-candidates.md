# Сначала каталог и группы-кандидаты, затем расширение банка

## Context and problem statement

К прежним разборам WebGen-Bench добавлены разборы train. Требования к отдельным
приложениям нельзя напрямую объявить универсальными проверками. Нужны ссылки на
исходники, выделение параметров и просмотр спорных объединений.

## Considered options

- Сразу добавить все исходные требования в configs/requirement-bank.json.
- Автоматически объединять требования по близости эмбеддингов.
- Сначала собрать каталог, вручную задать группы и найти лексических соседей по TF-IDF.

## Decision outcome

По обсуждению со студенткой выбран третий вариант. Загрузки моделей, API и внешние
LLM пока не используются. TF-IDF — временный способ поиска кандидатов, а не замена
семантической проверки. Согласование экспериментальной методики этим ADR не производится.

Старые глобальные ссылки webgen-<индекс>-<ID> сохраняются. Для train добавляется
пространство имён webgen-train-<WebGen ID>-<ID>. Локальные ID в исходных MD/JSON
не меняются. Родитель и зависимости получают соответствующие глобальные ссылки.

Группы из configs/requirement-families.json и совпадения поиска — черновые кандидаты.
Они не добавляются автоматически в исполняемый банк. Операции, роли, ограничения,
области цветов и зависимости необходимо проверить перед объединением.

### Consequences

- Исходные разборы и первая версия банка остаются неизменными.
- Сохраняется возможность пройти от группы к конкретному требованию и его ТЗ.
- Код проверки не считается реализованным только из-за исходной метки code.
- Карта — проекция TF-IDF, её расстояния не доказывают эквивалентность требований.
- Train-разборы, используемые при разработке банка, нельзя затем считать независимой
  отложенной проверкой переноса.

## Pros and cons of the options

Прямое копирование сохраняет всё, но не даёт переиспользуемых шаблонов.
Эмбеддинги полезны для дальнейшего поиска, но сейчас их нет для новых требований;
студентка выбрала работу без загрузок. TF-IDF доступен локально, но чувствителен к
формулировкам и не учитывает смысл достаточно надёжно. Поэтому решение об объединении
остаётся ручным.
