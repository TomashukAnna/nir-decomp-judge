# Пробный запуск DevAI на внутреннем API или кластере

Работа по issue #4. Цель передачи преподавателю — получить один ответ модели на задачу 39. Сравнение с человеческой разметкой студентка выполняет после получения ответа. Подготовка данных и проверка входа не требуют ключа.

## Получить код

Для новой рабочей копии:

```sh
git clone --branch docs/devai-data-smoke-test --single-branch https://github.com/TomashukAnna/nir-decomp-judge.git
cd nir-decomp-judge
```

Если эта ветка уже скачана, выполните `git pull --ff-only` из её чистой рабочей копии.

## Окружение

Нужны Git, Python >= 3.12 и uv. Команды выполняются из корня `nir-decomp-judge`; одинаковы для PowerShell и Linux:

```sh
uv sync --locked
```

## Скачать данные и собрать промпт

```sh
uv run python -m decomp_judge.prepare_devai --source data/external/agent-as-a-judge --output data/devai-smoke/task39 --download
```

Скрипт клонирует https://github.com/metauto-ai/agent-as-a-judge.git, если папки источника ещё нет. Git-коммит и задача берутся из `configs/devai-smoke.yaml`:

- коммит `43c2fa7b84ef0c1522e8250576e6798bace29dd0`;
- задача `39_Drug_Response_Prediction_SVM_GDSC_ML`;
- опубликованный проект OpenHands;
- ожидаемые ID требований: 0–6.

Файлы читаются непосредственно из объектов указанного Git-коммита. Размеры в дереве также берутся из Git, а не из рабочей копии с возможными CRLF. Поэтому размеры некоторых текстовых файлов отличаются от первоначального локального промпта, при сохранении их текста. Текущая ветка и переводы строк в рабочей копии источника не меняют новый промпт. Чужой код не исполняется. Дата подготовки и хеш сообщений сохраняются в manifest.

Если репозиторий уже скачан, его можно использовать без сети:

```sh
uv run python -m decomp_judge.prepare_devai --source ../agent-as-a-judge --output data/devai-smoke/task39
```

Выходная папка должна быть новой: существующие файлы не перезаписываются. Для повторной подготовки задайте другой `--output`.

## Результат подготовки

В выходной папке будут:

- `messages.json` — сообщения для модели;
- `prompt.txt` — читаемая копия запроса;
- `manifest.json` — версия данных, состав материалов и SHA-256 сообщений.

Системная инструкция находится в `configs/devai-system.txt`. Пользовательское сообщение содержит исходную задачу, требования, дерево проекта и полные тексты файлов `.py`, `.md`, `.txt`. Остальные файлы представлены путями и размерами. Папка `judge` исключена; человеческая разметка не читается и в запрос не включается. PDF, PNG и CSV не передаются содержимым.

`data/` уже исключена через `.gitignore`: исходный датасет и подготовленный промпт в Git не добавляются. В репозитории хранятся код сборки, конфигурация и системная инструкция.

## Проверка без модели

```sh
uv run python -m decomp_judge.devai_smoke --config configs/devai-smoke.yaml --messages data/devai-smoke/task39/messages.json
```

Ожидается `DRY RUN`, два сообщения и ID `[0, 1, 2, 3, 4, 5, 6]`. Это проверка входа, а не доступности модели.

## Настроить внутренний API

Настройки задаются переменными окружения, поэтому менять YAML и делать новый коммит для другого сервера не требуется. Адрес ниже — пример: преподаватель подставляет доступный ему OpenAI-совместимый endpoint и реальное имя модели на этом сервере. `DEVAI_API_BASE` — базовый URL, обычно заканчивающийся на `/v1`, без `/chat/completions`.

Linux / Bash (в том числе внутри выделенной сессии или задания кластера):

```bash
export DEVAI_API_BASE="http://INTERNAL_HOST:PORT/v1"
export DEVAI_MODEL="iairlab/qwen3.8-27b"
export DEVAI_CUSTOM_LLM_PROVIDER="openai"
export SEED=42
read -rsp 'LLM API key: ' LITELLM_API_KEY
printf '\n'
export LITELLM_API_KEY
```

Если ключ уже передан окружением задания или хранилищем секретов, повторно вводить его не нужно. В неинтерактивном задании `read` не используется. Для обращения к API GPU на клиентской машине не требуется; нужен сетевой доступ к серверу модели. Данные можно подготовить на машине с интернетом и перенести папку `data/` на кластер вместе с рабочей копией кода той же версии.

PowerShell — эквивалент настройки адреса и модели:

```powershell
$env:DEVAI_API_BASE = 'http://INTERNAL_HOST:PORT/v1'
$env:DEVAI_MODEL = 'iairlab/qwen3.8-27b'
$env:DEVAI_CUSTOM_LLM_PROVIDER = 'openai'
$env:SEED = '42'
```

Ключ должен находиться в переменной окружения процесса `LITELLM_API_KEY`. Если он ранее сохранён в пользовательской переменной Windows, загрузите его без вывода на экран:

```powershell
$env:LITELLM_API_KEY = [Environment]::GetEnvironmentVariable('LITELLM_API_KEY', 'User')
```

`DEVAI_CUSTOM_LLM_PROVIDER=openai` выбирает адаптер LiteLLM, а `DEVAI_MODEL` передаёт имя модели. Поэтому здесь имя указано как `iairlab/qwen3.8-27b`. Без переопределений используется конфигурация лабораторного API из YAML с маршрутизирующим префиксом `openai/`.

При необходимости доступны `DEVAI_MAX_TOKENS`, `DEVAI_TIMEOUT_SECONDS`, `DEVAI_PR`. Фактическая конфигурация сохраняется отдельно от исходного YAML; ключ в неё не входит. Скрипт не загружает `.env`.

## Сделать один запрос

Повторите проверку без модели после установки переменных: она выведет выбранные имя модели и адрес API. Затем из чистой рабочей копии выполните:

```sh
uv run python -m decomp_judge.devai_smoke --config configs/devai-smoke.yaml --messages data/devai-smoke/task39/messages.json --output data/devai-runs/internal-001 --execute
```

Скрипт вызывает LiteLLM один раз, без автоматических повторов. Запуск записывается в локальный MLflow (`mlflow.db`); запускать веб-интерфейс MLflow не требуется. Папка результата должна быть новой. Для отдельного запуска на кластере используйте, например, `--output data/devai-runs/cluster-001`.

## Что вернуть

Из папки результата нужны:

- `raw-response.txt` — исходный текст ответа модели до проверки JSON;
- `run.json` — ID MLflow, коммит кода и данных, seed, задача и хеш сообщений;
- `effective-config.json` — фактические параметры модели и API без ключа;
- `verdicts.json` — разобранный ответ, если он соответствует ожидаемой схеме.
