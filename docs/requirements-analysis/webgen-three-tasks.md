# Разбор трёх примеров ТЗ WebGen-Bench

Задание: Здесь есть ТЗ: https://github.com/mnluzimu/WebGen-Bench/blob/main/data/test.jsonl Нужно взять три задания. Для каждого построить иерархию требований, для каждого требования написать проверочное правило и отметить, детерминированное оно или LLM. Отдельно записать места, где задание допускает двойное прочтение, и какое прочтение выбрано.

Результат:

Набор данных выше был подготовлен в рамках статьи: WebGen-Bench: Evaluating LLMs on Generating Interactive and Functional Websites from Scratch

В статье рассматривается вопрос: Как объективно измерить, насколько сайт, сгенерированный LLM-агентом по текстовому ТЗ, действительно удовлетворяет этому ТЗ?

Авторы сначала изучили реальные заказы на разработку сайтов, затем сформировали типовые приложения и требования к ним. С помощью GPT-4o преобразовали их в естественно сформулированные задания для генерации сайтов. После всех действий получилось 101 заданий, которые делятся на три большие группы:

Content Presentation - визуализации данных, дашборды.

User Interaction – формы обратной связи, чаты, коммуникация

Data Management - обработка данных, работа с файлами

Поэтому были рассмотрены 3 ТЗ из разных групп.

| Расчет присутствия | Разница между первым приходом и последним уходом или сумма отдельных рабочих интервалов. | Сумма зарегистрированных интервалов «начало - окончание». Пересекающиеся интервалы не должны учитываться дважды. |
| Перерывы | Включаются в присутствие или вычитаются. | Не требуем отдельного учета перерывов. Если перерыв оформлен окончанием и последующим началом работы, этот промежуток не входит в присутствие. |
| Повторные отметки | Несколько приходов подряд допустимы или должны отклоняться. | Повторное начало при уже открытом рабочем периоде не создает второй одновременно открытый период. |
| Незавершенный рабочий период | Считать до текущего времени, исключить из расчета или автоматически закрыть. | Для основной проверки расчетов используем завершенные периоды.  |
| Perform statistics | Любые агрегаты или конкретный набор показателей. | Суммарное время присутствия и отсутствия по сотрудникам за выбранный период. |
| Perform analysis | Графики и сравнения или обязательный текстовый аналитический отчёт. | Достаточно представления, позволяющего сравнить сотрудников или периоды. |
| Время и часовой пояс | Локальное время устройства или единое время системы. | Для проверки используем один заранее установленный часовой пояс; отметки сравниваем как моменты времени. |
| All components dark orange | Все части компонентов, включая текст, или их основной цвет. | Основной фон кнопок, карточек и панелей — dark orange. Текст и значки могут быть контрастными. |
