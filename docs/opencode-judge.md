# Агент-судья через OpenCode: подготовка

Ветка `feat/opencode-readonly-judge` продолжает работу после принятого PR #5. Это подготовка агента с инструментами чтения и поиска. Она не является воспроизведением Agent-as-a-Judge из статьи и пока не содержит результатов оценки агентом.

## Что меняется

В предыдущем запуске Python заранее собирал исходники в одно сообщение. Теперь модель получает задачу, а OpenCode исполняет её запросы на чтение файлов и возвращает результаты следующему обращению к модели. Несколько обращений к модели и инструментам составляют одну агентную сессию.

Первый тест будет проверять только способность самостоятельно прочитать `src/model.py` и назвать реализацию регрессора с указанием строк. Полная оценка семи требований и сравнение с человеком выполняются позже. Путь к файлу в коротком задании допустим; содержимое файла в него не включается.

## Компоненты

- `configs/opencode-judge.json`: провайдер, модель, разрешения и агент `requirements-judge`.
- `configs/opencode-judge-system.txt`: инструкция исследовать свидетельства, приводить пути/строки, различать код и опубликованные артефакты, не исправлять проект.
- `src/decomp_judge/prepare_opencode.py`: сборка отдельной папки из Git-объектов DevAI. Повторно использует зафиксированную версию из `configs/devai-smoke.yaml`.

Провайдер `lab` — локальное имя подключения в OpenCode. Полная запись `lab/iairlab/qwen3.8-27b` выбирает его и модель `iairlab/qwen3.8-27b`. `@ai-sdk/openai-compatible` — адаптер OpenCode; Python-библиотека LiteLLM для этого вызова не используется. Адрес лабораторного API остаётся тем же.

В конфигурации записана ссылка `"apiKey": "{env:LITELLM_API_KEY}"`, а не значение ключа. При запуске OpenCode подставляет переменную окружения процесса.

Разрешены `read`, `glob`, `grep`; остальные инструменты запрещены правилом `"*": "deny"`. Явно запрещён выход за рабочую папку через `external_directory`. Таким образом, агенту не разрешены оболочка, изменение файлов, сеть через инструменты и запуск других агентов. Это разрешения инструментов OpenCode, не отдельная изоляция процесса средствами ОС. Сам OpenCode обращается к API модели и может скачивать зависимости адаптера.

Ограничение `steps: 8` задаёт максимум агентных итераций перед принудительным текстовым завершением. Это не лимит токенов и не гарантия ровно восьми запросов: служебные обращения harness также требуют учёта при настоящем запуске.

## Установленная версия

Переносимый официальный OpenCode **1.19.4**, Windows x64:

- [Архив релиза](https://github.com/anomalyco/opencode/releases/download/v1.19.4/opencode-windows-x64.zip).
- Локальный исполняемый файл: `data/tools/opencode/1.19.4/opencode.exe`.
- SHA-256 скачанного архива: `93b899277bd6f68803009e32bf71772ce43c34b18adf1e93b9b4d8780fdf62e5` (локально вычисленный отпечаток, не независимая подпись).

Архив и программа находятся в игнорируемой `data/` и в Git не добавляются. Проверка версии:

```powershell
& .\data\tools\opencode\1.19.4\opencode.exe --version
```

## Подготовить папку проекта

Из корня исследовательского репозитория:

```powershell
uv run python -m decomp_judge.prepare_opencode --source ../agent-as-a-judge --output data/opencode-smoke/task39
```

Если источника нет, укажите `--download`. Папка результата должна быть новой. Скрипт создаёт:

- `data/opencode-smoke/task39/workspace/` — файлы опубликованного проекта, без `judge/` и человеческой разметки;
- `data/opencode-smoke/task39/manifest.json` — версия источника и хеши файлов.

Файлы берутся из коммита `43c2fa7b84ef0c1522e8250576e6798bace29dd0`, а не из изменяемой рабочей копии. Опубликованные пути сохраняются, в том числе `results/performance.txt`. Изображения, PDF и CSV копируются без изменения байтов; возможность их чтения агентом зависит от конкретного инструмента и модели и не предполагается заранее. Это отличается от прежнего текстового промпта и должно учитываться в будущем сравнении.

Внутри workspace создаётся пустая `.git` как граница проекта, чтобы OpenCode не подхватил инструкции исследовательского репозитория из родительских папок. Указания `AGENTS.md`, `CLAUDE.md` и конфигурации OpenCode внутри оцениваемого проекта отклоняются до записи файлов. Служебная `.git` не является частью опубликованного проекта. Исходный репозиторий DevAI не изменяется.

- Автоматические тесты проверяют сохранение байтов из зафиксированного коммита вопреки изменениям рабочей копии, исключение разметки и judge, хеши, запрет перезаписи и конфигураций внутри оцениваемого проекта.

## Первый запуск с MLflow

Обёртка `decomp_judge.opencode_smoke` записывает коммит кода, версию OpenCode, конфигурацию, системную инструкцию, задание, manifest, поток событий, stderr и итоговый ответ. Перед запуском требуется чистая закоммиченная рабочая копия. Ключ берётся из окружения процесса, файлы `.env` не загружаются. Текстовые артефакты проходят удаление известного ключа и Bearer-токенов перед сохранением.

Задание хранится в `configs/opencode-file-smoke.txt`. Оно просит прочитать один файл, не передавая его содержимое. Проверка без запуска модели:

```powershell
uv run python -m decomp_judge.opencode_smoke --executable data/tools/opencode/1.19.4/opencode.exe --prepared data/opencode-smoke/task39 --output data/opencode-runs/read-001
```

Для настоящей сессии загрузите ключ в окружение текущего процесса и добавьте `--execute`:

```powershell
$env:LITELLM_API_KEY = [Environment]::GetEnvironmentVariable('LITELLM_API_KEY', 'User')
uv run python -m decomp_judge.opencode_smoke --executable data/tools/opencode/1.19.4/opencode.exe --prepared data/opencode-smoke/task39 --output data/opencode-runs/read-001 --execute
```

Папка результата должна быть новой. Лимит времени сессии по умолчанию 600 секунд, можно изменить через `AGENT_TIMEOUT_SECONDS`. Версия проверяется по `AGENT_EXPECTED_VERSION` (по умолчанию 1.19.4). Интерфейс MLflow открывать не требуется. Seed сохраняется из настроек проекта, но эта обёртка не навязывает его адаптеру модели: это явно отражено в параметре `seed_applied_to_model=false`, детерминизм не обещается.

Успех подтверждается завершённым событием `read` для `src/model.py` с непустым результатом, итоговым текстовым ответом и неизменностью файлов. Проверка хешей выполняется до и после сессии; также обнаруживаются новые файлы вне служебной `.git`. Сам текст итогового ответа не является доказательством вызова инструмента. При тайм-ауте или ошибке сохраняются доступные события и диагностика, запуск MLflow помечается неуспешным.

В папке результата находятся `run.json`, `config.json`, `system.txt`, `task.txt`, `manifest.json`, `events.jsonl`, `stderr.txt`, `summary.json`, `final-response.txt`; при ошибке — `error.json`. Вложенная `runtime/` — отдельные каталоги состояния OpenCode. Вся папка расположена в игнорируемой `data/`. Эти события могут содержать прочитанный исходный код, поэтому целиком автоматически в Git не добавляются.

После технического smoke test можно переходить к оценке требований; первый тест не присваивает им PASS/FAIL.

При подготовке реального запуска используются отдельные XDG-каталоги состояния, отключение сторонних плагинов (`--pure`), загрузки чужих skills, автообновления и каталога моделей. Команду `debug config` нельзя выводить с реальным ключом: разрешённая конфигурация содержит подставленное значение. Рабочая папка агента должна быть `workspace/`, а не весь репозиторий DevAI с разметкой.
