# Агент-судья на OpenCode

OpenCode 1.19.4 подключается к лабораторному API и даёт модели инструменты чтения и поиска. Редактирование, запуск команд, веб-поиск и доступ за пределы рабочей папки запрещены.

## Конфигурация

Основные настройки issue #8 находятся в `opencode.json`:

- API: `https://api.duckduck.cloud/v1`;
- модель: `iairlab/qwen3.8-27b`, подключение в OpenCode — `lab`;
- ключ: из переменной окружения `LITELLM_API_KEY`;
- лимит агентных итераций: 8.

Инструкция судьи — `configs/judge-agent.md`, подключена в `opencode.json`. Вход: ТЗ, JSON требований и каталог приложения. Выход: `verdicts` с ID, PASS/FAIL/NA, ссылками на файлы и строки и однострочной причиной. PASS требует свидетельства; NA означает неприменимость или невозможность оценки разрешёнными средствами. Для FAIL/NA допускается пустое evidence с объяснением отсутствия или недоступности свидетельств. Примеры задач и заранее разобранные кейсы в инструкцию не включены. Программная проверка общей схемы и свидетельств будет добавлена вместе с новым запуском судьи.

## Запуск судьи

`src/decomp_judge/judge_agent.py` принимает три входа: `--spec` — UTF-8 файл с текстом ТЗ, `--requirements` — JSON-массив объектов с `requirement_id` и `criteria`, `--app` — каталог приложения. Строковые и целочисленные ID сохраняются без преобразования. Лишние поля требований не передаются модели; человеческие метки в запрос не включаются. Входные файлы для задачи 39 подготовим на этапе прогона.

Из корня исследовательского репозитория:

```powershell
uv run python -m decomp_judge.judge_agent --spec data/judge-input/spec.txt --requirements data/judge-input/requirements.json --app data/judge-input/app
```

Без `--execute` проверяются только входные данные: ключ и OpenCode не нужны. Для настоящего запуска добавляются `--execute --executable data/tools/opencode/1.19.4/opencode.exe --output data/judge-runs/run-001`. Требуются ключ в окружении и чистая закоммиченная рабочая копия. Папка результата должна быть новой и находиться вне приложения.

Используется корневой `opencode.json` и `configs/judge-agent.md`. OpenCode работает без интерактива в каталоге приложения; чужие конфигурации и skills отключены. Температура принудительно равна 0; лимит шагов — 8, переопределяется через `--max-steps` или `JUDGE_MAX_STEPS`. Лимит времени — `JUDGE_TIMEOUT_SECONDS`, по умолчанию 600 секунд. Температура 0 не гарантирует одинаковые ответы; seed записывается, но не навязывается адаптеру.

В MLflow и папке результата сохраняются:

- `raw-output.jsonl` — сырой stdout OpenCode, `stderr.txt` — диагностика;
- `trace.json` — события инструментов, `raw-response.txt` — текст последнего шага;
- `verdicts.json` — ответ, прошедший проверку схемы, ID, файлов и строк;
- `tokens.json` — счётчики шагов и суммы, `timing.json` — секунды и проверка неизменности приложения;
- `run.json`, `config.json`, `prompt.txt`, `manifest.json` — версия кода, фактические настройки, запрос и хеши файлов.

Из сохраняемых текстов удаляются известный ключ и Bearer-токены. Суммы токенов относятся к опубликованным событиям `step_finish`, не обязательно включают служебные обращения OpenCode. Отсутствующие счётчики не подменяются нулями. При ошибке сохраняется `error.json` и доступный вывод; MLflow-run помечается неуспешным. Проверка ссылок не доказывает смысловую правильность вердикта.

Ниже сохранены команды прежней технической проверки одного файла, использующей `configs/opencode-judge.json` и `opencode_smoke.py`.

## Подготовка задачи 39

Команды выполняются из корня репозитория. OpenCode установлен в `data/tools/opencode/1.19.4/opencode.exe`.

```powershell
uv sync --locked
uv run python -m decomp_judge.prepare_opencode --source ../agent-as-a-judge --output data/opencode-smoke/task39
```

Если источника нет, добавьте `--download`. Скрипт создаёт отдельную папку `workspace/` из коммита DevAI `43c2fa7b84ef0c1522e8250576e6798bace29dd0`, без человеческой разметки и каталога `judge/`. Хеши файлов сохраняются в `manifest.json` рядом с ней. Существующая папка результата не перезаписывается.

## Проверка чтения файла

Запускать из чистой закоммиченной рабочей копии. Ключ должен быть доступен в окружении процесса. Если он сохранён в пользовательской переменной Windows:

```powershell
$env:LITELLM_API_KEY = [Environment]::GetEnvironmentVariable('LITELLM_API_KEY', 'User')
uv run python -m decomp_judge.opencode_smoke --executable data/tools/opencode/1.19.4/opencode.exe --prepared data/opencode-smoke/task39 --output data/opencode-runs/read-002 --execute
```

Без `--execute` запрос к модели не отправляется. Для повторного запуска укажите новую папку `--output`.

Проверка успешна, если в трассе есть завершённое чтение `src/model.py`, получен итоговый ответ и файлы проекта не изменились. Пройденный запуск: MLflow `fe8a4ce78a25485ea2300a0da8b71586`, [отчёт](../results/opencode/read-001/report.md). Это технический тест, не оценка требований.

## Результаты

Сессия записывается в MLflow и папку `--output`. Основные файлы:

- `events.jsonl` — события и вызовы инструментов;
- `final-response.txt` — ответ модели;
- `summary.json` — результат проверок;
- `run.json`, `config.json`, `manifest.json` — сведения о запуске и входных данных;
- `stderr.txt`, при ошибке `error.json` — диагностика.

Исходники, состояние OpenCode и полная трасса остаются в игнорируемой папке `data/`. Ключ в конфигурацию и Git не записывается.
