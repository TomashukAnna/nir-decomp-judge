# Проверка запуска и исходников

Судья получает ТЗ, список требований, исходное приложение и отдельную рабочую копию с установленными зависимостями. Подготовьте чистую рабочую копию кода судьи и переменную LITELLM_API_KEY для лабораторного API.

```powershell
uv run --with playwright==1.52.0 python -m decomp_judge.browser_judge `
  --app PATH_TO_SOURCE --runtime-app PATH_TO_RUNTIME_COPY `
  --spec PATH_TO_SPEC --requirements PATH_TO_REQUIREMENTS_JSON `
  --opencode PATH_TO_OPENCODE --output PATH_TO_NEW_OUTPUT
```

Сейчас распознаются сценарий dev на Vite, команды запуска Python в README без аргументов и точки входа Python в корне приложения или src. При неопределённой команде все требования передаются судье по исходникам. Для установленного Edge можно добавить --channel msedge.

На функциональном этапе модель получает наблюдения запуска и выбирает действия. Для веб-приложения доступен Playwright. Для Python доступны чтение локальных файлов для планирования и вызовы публичных функций с аргументами JSON. Функциональные PASS и FAIL требуют ссылки на наблюдение. Остальные требования передаются OpenCode одним пакетом. Отчёт содержит источник решения и причину перехода к исходникам.

Запускайте доверенные приложения в изолированной среде. Отдельная копия и сокращённое окружение процесса не заменяют системную изоляцию. Журналы действий и наблюдения сохраняются локально, итог функционального этапа и счётчики токенов записываются в MLflow.
