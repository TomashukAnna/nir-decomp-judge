# Декомпозиционная оценка покрытия требований автоматически сгенерированным программным обеспечением: гибридный чек-лист-судья и его надёжность

[English version](README.md)

Семестровая научно-исследовательская работа Анны Томашук.

## Проблема и цель

Мультиагентные LLM-системы создают веб-приложения по текстовому техническому заданию (ТЗ). Проверка выполнения ТЗ требует человеческой оценки либо оценки LLM-судьи. Целостная оценка одним промптом сама нуждается в проверке надёжности.

Цель работы — разработать гибридного чек-лист-судью для декомпозиционной оценки покрытия требований и исследовать его надёжность, стоимость и устойчивость к смещениям.

## Предлагаемый подход

1. Из текстового ТЗ извлекается иерархия требований.
2. Каждому требованию сопоставляется правило проверки: детерминированное или основанное на LLM.
3. Судья выполняет правила на артефактах сгенерированного веб-приложения.
4. К каждому вердикту прикладывается свидетельство, на основании которого он вынесен.

## Исследовательский вопрос

Надёжнее ли, дешевле ли и устойчивее ли к смещениям декомпозиционный гибридный судья, чем целостная оценка одним промптом и агентный судья Agent-as-a-Judge?

Сравнение планируется проводить в одинаковых условиях. Гипотезы будут сформулированы и зафиксированы до экспериментов. Анализ должен показать, где декомпозиция помогает, а где не даёт преимуществ.

## Ожидаемые результаты

- Репозиторий с реализацией судьи и воспроизводимыми конфигурациями экспериментов.
- Корпус требований с разметкой и оценкой согласия аннотаторов.
- Препринт с гипотезами, зафиксированными до экспериментов, сравнением методов в одинаковых условиях, размерами эффектов и доверительными интервалами.
- Презентация результатов исследования.

Работа находится на этапе подготовки. Исследовательские эксперименты ещё не проведены; метрики и протокол сравнения предстоит определить.

## Быстрый старт

Текущий `smoke` — демонстрация инфраструктуры из шаблона на синтетических данных, а не оценщик требований. В Windows нужны Git, Python >= 3.12, uv и GNU Make; запускайте команды из корня репозитория. Git Bash нужен для shell-хуков шаблона.

```bash
uv sync --locked
uv run pre-commit install
make check
uv lock --check
```

В Windows без разрешения на символические ссылки навыки открываются напрямую из `.agents/overlay/skills/<skill>/SKILL.md`. После установки инструментов перезапустите Codex, чтобы он получил обновлённый PATH.

В Windows создавайте коммиты через `uv run git commit`: так Git-хук получает доступ к pre-commit из `.venv`, в том числе при кириллице в пути проекта.

## Структура

```
src/<пакет>/         код, который импортируется и тестируется: config.py, pipeline.py, __main__.py
tests/               smoke-тест: пайплайн на крошечном входе
configs/             конфиги экспериментов (YAML)
notebooks/           исследовательский анализ; вывод ячеек можно оставить как отчёт о результате
docs/adr/            журнал решений, один файл на решение
docs/meetings/       записи встреч
docs/reading-log.md  журнал чтения статей
data/                не попадает в репозиторий; как получить данные, написано ниже
results/             таблицы и рисунки, экспортированные из кода
.github/             шаблон PR, форма issue для экспериментов, CODEOWNERS, CI
```

## Данные

Данные в репозиторий не кладутся, в том числе открытые бенчмарки. Кандидат для исследования — WebGen-Bench; версия, источник и процедура получения будут зафиксированы после выбора набора данных. Существующие локальные данные находятся вне репозитория в родительской папке `data WebGen-Bench`.

## Эксперименты

Каждый запуск записывается в MLflow (`MLFLOW_TRACKING_URI` в `.env`, по умолчанию локальная база `mlflow.db`). Строка результата: коммит, путь к конфигу, seed, id запуска, метрики.

## Проверки

`make check` запускается из трёх мест: pre-commit на вашей машине, CI на каждом PR, хук агента. Ветка `<тип>/<короткое-описание>`, заголовок PR `<тип>: ...`; типы: feat, fix, refactor, docs, test, chore, exp. Подробно: [правила работы с git и GitHub](docs/git-workflow.ru.md).

## LLM-ассистенты

Codex используется для настройки репозитория, помощи с кодом, проверками и документацией. Автор проверяет изменения и отвечает за научные выводы. Инструкции для них: [AGENTS.md](AGENTS.md); общие правила лаборатории уже подключены как подмодуль `.agents/overlay` на теге v0.1.0 ([nir-agent-overlay](https://github.com/Industrial-AI-Research-Lab/nir-agent-overlay)); другую версию подключает `make overlay OVERLAY_VERSION=<тег>`. За код, написанный с агентом, отвечаете вы.
